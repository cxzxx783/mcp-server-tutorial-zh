# 01 - 认识 MCP

## 一句话理解

> **MCP = AI 的 USB 接口**

就像电脑插上 USB 就能接鼠标/键盘/U盘一样，MCP 让 AI 能接上各种工具和数据源——查数据库、读文件、搜网页、操作软件……统一一套协议，不用每家 AI 单独适配。

## 解决了什么问题？

没有 MCP 之前，给 AI 加个工具你得：
- 每个 AI 客户端（Claude/ChatGPT/各种）各自实现自己的插件系统
- 工具开发者要为 N 个平台分别写适配
- 换 AI 就得重写一遍

MCP 就像 **USB 标准**：工具写一次，任何支持 MCP 的 AI 都能用。

## 架构长什么样？

```
你的 AI 应用 (Claude / Cherry Studio / 自定义)
        │
        │   MCP 协议 (JSON-RPC over stdio/SSE)
        │
   ┌────┴────┐   ┌──────────┐   ┌──────────┐
   │ MCP     │   │ MCP      │   │ MCP      │
   │ Server  │   │ Server   │   │ Server   │
   │ (搜索)  │   │ (文件)   │   │ (数据库) │
   └─────────┘   └──────────┘   └──────────┘
```

**三个角色：**

| 角色 | 是谁 | 干啥 |
|------|------|------|
| **MCP Host** | Claude Desktop / Cherry Studio / 你的程序 | 用户面对的程序，负责连接 AI + MCP |
| **MCP Client** | Host 内部组件 | 和 Server 一对一通信 |
| **MCP Server** | 你写的这个教程的主角 | 提供工具和数据，每个 Server 专注一件事 |

## MCP 的三大能力

| 能力 | 相当于 | 应用场景 |
|------|--------|----------|
| **Tool（工具）** | AI 能调用的函数 | 搜索、查天气、发邮件、操作文件 |
| **Resource（资源）** | AI 能读取的数据 | 读取配置文件、日志、数据库记录 |
| **Prompt（提示模板）** | 预设的 AI 指令 | 快速启动特定任务模式 |

**日常开发 90% 用 Tool**——也是本教程的重点。

## MCP vs 传统 API

| | 传统 API | MCP |
|--|---------|-----|
| 谁来调 | 你写代码调 | AI 自己决定调不调 |
| 连接方式 | 自己写 HTTP 请求 | 自动管理连接 |
| 多工具 | 每个工具独立集成 | 统一协议即插即用 |
| 学习成本 | 每次重新学 | 学会一次通用 |

## 什么时候需要用 MCP？

- 想让 AI **访问你的本地文件**
- 想让 AI **实时搜索网页**（不是训练数据里的旧内容）
- 想让 AI **操作某个软件/系统**
- 想做自己的 **AI 自动化工具链**
